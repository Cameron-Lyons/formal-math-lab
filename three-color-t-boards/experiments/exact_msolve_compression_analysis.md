# Further exponent compression and quotient-aware F4: static assessment

This is source analysis only. No additional solver build or full computation was performed for this note. Source references are relative to the preserved seventh checkout, `exact_msolve_symbolic_reserve_tools/msolve-cc044551f8e202d00691990fd3fd0b1226a88ea2/src/`. The checked byte build has separate validation and provenance in `exact_msolve_byte_exponent_tools/README.md`.

## What the measured matrices imply

The last completed matrix of the 3-GiB minimum-fill trial (`exact_msolve_full_native3_minfill_symbolic_3g.log`) has 17,439 rows and 3,200,323 columns. Its reported nonpivot count is 3,182,900, leaving only 17,423 known-pivot columns, about 0.5444%. Returned rows reference 2,962,178 columns. Symbolic preprocessing tests every introduced monomial against the active leading ideal; that ideal includes a divisor of each field cube. Consequently every field-reducible monomial is among the known-pivot columns. More than 99.45% of this matrix's columns are already field-normal, with every coordinate exponent at most two.

This bounds the benefit of **only deleting field-reducible columns of that existing matrix** by 0.55%. A different construction that cancels S-polynomial supports before inserting columns may produce a different matrix, so the statistic does not rule out an algorithmic improvement. It does rule out assuming that field normalization alone will remove most observed columns.

The run failed cleanly during a later symbolic reservation: load 3,624,513 plus source-row length 1,875,945 plus one spare requested 5,500,459 entries, rounded to 5,505,024. Previously confirmed symbolic capacity was 5,177,344. At 97 lanes/vector, the old uint16 principal symbolic arrays would total 1,208.5 MiB at that requested target; smallest sufficient power-of-two allocation would total 1,808 MiB. The failed target was not successfully allocated. This comparison concerns one measured request, not process RSS or an equivalent step in a differently ordered input.

## Representation options after byte storage

`neogb/data.h:85` defines `exp_t`; the vector layout includes a total-degree lane. Byte storage is unusually local because existing allocation/copy paths already scale with `sizeof(exp_t)`. Further sub-byte or sparse formats cannot preserve ordinary C indexing: the implementation directly reads `ht->ev[id][coordinate]` and caches `exp_t **` arrays throughout `hash.c`, `order.c`, `symbol.c`, `io.c` and final reduction in `f4.c`.

At total degree five a sparse coordinate list needs at most five (variable index, exponent) pairs, plus degree/count metadata: roughly 12 bytes instead of 97. This is a degree-specific estimate. Degree can rise to 193 in the supported 96-variable F3 model, and a dense monomial could make sparse storage worse than the byte vector. A hybrid representation requires exact ownership, lookup, comparison and multiplication routines rather than a typedef change.

A dense two-bit coordinate representation is particularly promising for normal monomials: 96 coordinates require 24 bytes plus a separate byte degree. All initial non-domain terms and ordinary promoted right-block terms have coordinates at most two; pure domains and pending pair LCMs have coordinates at most three. For symbolic terms outside that set, a checked escape representation must preserve higher coordinates. The invariant “symbolic coordinate at most five” does not survive recursive reductions; only the total-degree bound is general.

A universal two-bit claim for all basis-hash entries also needs care. Final interreduction (`f4.c:572ff`) uses the legacy all-column import after resetting all columns to the right block. That can import unused intermediate symbolic monomials with larger coordinates. An escape representation handles this safely; an alternative would require a separately audited support-only final import. Neither change is implemented here.

Packing would require accessors or explicit decode buffers at all direct exponent accesses, stable-ID and pointer-lifetime audits, exact hashing/comparison agreement, and staging/rehash/reset/copy tests. Four-bit coordinates reduce the exceptional set but still need checks: no proof here bounds every possible symbolic coordinate by 15. A checked four-bit implementation must fail nonzero or use an exact escape format, never truncate.

## A mathematically sound quotient-aware direction

Let J be the field ideal generated by all x_i^3-x_i, and let N be its canonical monomial normal-form map. Normalizing products is exact modulo J, but replacing the current F4 products with normalized ones is not a local optimization.

The current selected-pair constructor (`symbol.c:200ff`) groups parents sharing an ordinary LCM, emits one upper row and the remaining lower rows, and marks that LCM as a known pivot. Polynomial multiplication (`hash.c:1548ff`) preserves borrowed source coefficients. After normalization, monomials can collide or vanish, the leading term can change, and separately normalized parents may no longer supply the recorded LCM pivot. Fresh merged coefficient arrays would also violate existing ownership assumptions unless deliberately integrated with the LA input structures. `la_ff_8.c:97ff` distinguishes known reducer coefficients from newly computed coefficients.

A defensible replacement would:

1. Retain ordinary critical pairs, including pairs with every required field-domain generator.
2. Form explicit S-polynomials, then normalize them modulo J, merge monomial collisions and drop zero coefficients/rows before constructing the matrix.
3. For a field-normal monomial m reducible by a non-domain leading monomial, insert N((m/LM(g))*g). The leading m survives: normalization only lowers DRL terms, so normalized tails remain smaller.
4. Audit pair criteria, leading-ideal coverage, sugar/degree metadata, coefficient ownership and zero-row accounting. Keep J available for the ordinary basis/export interpretation.
5. Prove that completed processing establishes the ordinary Buchberger criterion for J+G; no implicit field critical pairs may be lost.

The field-pair requirement is essential. Over F3, `{x^3-x, x^2+1}` generates the unit ideal. If the normalized field polynomial is simply dropped and only the polynomial `x^2+1` remains, an ordinary pair algorithm may stop with quotient dimension two, although the intended F3 solution count is zero. The missing field pair generates a linear remainder and then the unit.

An alternative finite-algebra algorithm could close the span of normalized generators under multiplication by every variable, but its ambient vector space has dimension 3^96. Without a sparse on-demand reduction proof, this is an obstruction rather than a scalable counting implementation.

## Recommendation

First evaluate the independently reviewed checked byte build. If further memory reduction is required, normal-monomial packing with exact escapes has a strong representation-based justification and a substantial theoretical space benefit, but is a larger source change. Quotient-aware F4 is mathematically plausible with the explicit obligations above; the observed column statistics provide no evidence that it will deliver a comparable memory reduction. No ninth implementation is justified by this note alone.
