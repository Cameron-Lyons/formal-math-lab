# Eighth preserved build: checked byte exponents

This dedicated executable handles serial, exact sparse DRL basis export over F3. It stores each exponent lane in a single byte without reducing exponents modulo 256 or changing polynomial identities. Every reachable narrowing arithmetic step is checked before assignment; any overflow or unsupported input exits with a nonzero code before writing the completion marker.

- Executable: `msolve`, SHA-256 `63e52125aba520101ccc7f4f188c626824cf867ebbd80390fbd03ec8c606da76`
- Patch from the seventh build: `checked-byte-exponents.patch`, SHA-256 `b97f1f487c27c2a0ddf7641046c36d118451a6231ce3554a69be25e0f24f04c6`
- Provenance manifest: `source.json` (records the upstream v0.11.0 archive and commit, all predecessor patches, source/compiler/library hashes, and build commands)

All earlier builds are untouched. No full-board solve was run for this build.

## Accepted scope

The executable accepts ASCII expanded-polynomial files with canonical header `x1,...,xn`, characteristic 3, and 1 to 127 variables. Every variable must have an explicit two-term nonzero scalar multiple of `x_i^3-x_i` among the initial generators, and every other initial monomial must have all coordinates at most 2. Redundant field equations, zero polynomials, and unit polynomials are allowed when all field domains are present. Unsupported presentations are rejected rather than rewritten.

A raw-input guard checks the file before the upstream parser converts any integers. This narrow grammar accepts integer coefficients within signed `int32` range and monomial factors with nonnegative byte-range exponents. It verifies variable names, rejects duplicate factors and malformed tokens, and bounds term and generator counts. It accepts the syntax generated by this repository, while rejecting alternative headers, rationals, factored expressions, negative exponents, and numeric overflow.

Only standard flags for file/output, `-g 1` / `-g 2` export, LA option 2, one thread, reduced basis, genericity handling 0, verbosity, hash sizing/reset, and pair batch target are accepted. Rational arithmetic (`QQ`), other fields, signature methods, normal forms, saturation/colon, elimination, parametrization, binary input, and non-export paths are rejected. The core and common import functions repeat these field, order, and mode checks so enforcement does not depend on the CLI alone. Final interreduction runs with the same checked exponent arithmetic.

## Why one byte is enough for these models

Initially, every non-domain monomial has coordinates at most 2, and each domain generator is a pure cube minus its variable. The active leading-monomial ideal contains every pure cube, and removing a redundant basis element preserves that property because a surviving leading monomial divides the removed one (`update.c` and `f4.c`).

Ordinary symbolic preprocessing checks every introduced monomial and marks a left pivot whenever an active leading monomial divides it (`symbol.c:find_multiplied_reducer`, `symbolic_preprocessing`). Column partitioning places those pivots on the left (`convert.c:convert_hashes_to_columns`), and the exact sparse reducer exports new rows only from the right block (`la_ff_8.c:reduce_dense_row_by_known_pivots_sparse_ff_8`). Every monomial in a new ordinary basis polynomial is therefore irreducible by all pure cubes, so its coordinate exponents are at most 2.

From those bounds:

- The LCM of two non-domain leading monomials has total degree at most `2n`.
- The LCM of a pure cube and a non-domain leading monomial has total degree at most `2n+1`.
- The LCM of two pure cubes has total degree at most 6.

That gives a uniform bound of `max(6, 2n+1) <= 255` for `1 <= n <= 127`. The `6` matters at `n=2`; for the 96-variable board models, the bound is 193.

Under DRL order, no tail term has higher degree than its leading monomial, so multiplying a reducer to cancel a symbolic term never raises total degree. This holds recursively throughout symbolic preprocessing and final interreduction. Individual symbolic coordinates do not have to stay at most 5, because repeated reductions can shift degree between variables; the valid invariant is the total-degree bound, which also caps every nonnegative coordinate.

Runtime checks enforce safety independently of this proof. `checked_exp_value` rejects values outside `[0, 255]`, `checked_exp_add` widens before adding, and `checked_exp_sub` widens before subtracting. These helpers guard input-vector reads and degree sums, pair-LCM degree sums, polynomial multiplication, and pair/reducer multiplier differences. Copies, coordinate maxima, hashing, and comparisons only operate on already checked values, and the inactive signature-add helper is checked too. Normal-form, signature, saturation, elimination, and tracing paths are disabled instead of relying on this degree proof.

## Storage and compatibility

`exp_t` changes from `uint16_t` to `uint8_t`. Ordinary exponent vectors include the total-degree lane, so the 96-variable model has 97 lanes. All active allocations, copies, pointer strides, staging, and reset paths use `sizeof(exp_t)`. Exponent comparisons and hashing are scalar, while the AVX coefficient kernels work on separate coefficient types and stay unchanged. The entire pinned solver and its static project libraries are rebuilt with the new typedef rather than patching against older library binaries.

A 97-lane exponent vector drops from 194 bytes to 97 bytes. Metadata, bucket arrays, pointers, sparse row indices, and coefficients stay the same size. At the previous 3-GiB minimum-fill trial's failed symbolic target of 5,505,024 slots, the exponent slab would shrink by 509.25 MiB; at its last reported basis capacity of 3,801,088 slots, it would shrink by 351.625 MiB. These figures compare theoretical slab sizes at fixed capacities and are not measured process-memory savings. Other arrays, transient `realloc` copies, and unchecked upstream allocations can still fail, so no speed or full-count completion guarantee follows.

## Validation

- `validation.json`: 26 paired completed `-g 1` / `-g 2` runs comparing this build to the seventh executable. Every export is byte-identical, with one completion marker and no error diagnostics. Eleven small F3 models agree with exhaustive enumeration and both independent integer staircase counters. The natural-F3 nine-row board fiber gives quotient dimension 6 directly, and the 127-independent-domain fixture gives `3^127` (checking both the maximum variable count and the large-integer counting path). No unrestricted board model was solved.
- `guard_check.json`: 39 rejected parser, model, and mode cases (missing or wrongly signed domains, unreduced non-domain terms, field mismatches, malformed variables or factors, huge exponents or coefficients, negative or missing exponents, total degree 381, 128 variables, option integer wrap, and unsupported execution modes). Every case exits nonzero with no completion marker and no nonempty basis export.
- `arithmetic_check.py`, `.c`, `.json`: extracts the arithmetic functions, input-vector conversion, LCM construction, and polynomial multiplication into an ASan+UBSan harness. It passes all 65,792 valid byte additions and subtractions, all 256 scalar values, input degrees 254 and 255, a 127-variable LCM of degree 255, and 11 synthetic overflow/underflow cases that exit before narrowing. Hash insertion uses a vector-capture stub, so this harness does not test allocator or probing behavior; the full basis comparisons cover the integrated tables.

The earlier draft is kept in `rejected_attempt1/`. A missing-domain test revealed that guarding only `initialize_gba_input_data` missed the prime CLI's `initialize_modular_trace` route. The final build checks both the parsed CLI model and the shared `import_input_data` boundary while keeping the original engine guard. No full trial ran on the rejected draft, and all valid-model comparisons were rerun after the fix. A later comment-only edit corrected the proof formula to `max(6, 2n+1)`, and a rebuild confirmed identical executable bytes.

Independent review passed on the exact frozen source, patch, and executable above:

- 20 independent small ideals produced 80 `-g 1` / `-g 2` exports matching the seventh build, Python Buchberger, and direct F3 enumeration, plus 34 independent parser/scope rejections.
- Actual-source ASan+UBSan arithmetic tests passed 65,792 byte cases, 1,200 input-index/LCM/two-term-product cases, the degree-6 and degree-255 boundaries, and 14 failure cases.
- The actual unrestricted minimum-fill input passed the source-only raw and model audit without running a solver.

## Reproduction

`prepare.py` extracts the pinned source, applies the recorded predecessor patches, and runs `finish_scope_fix.py`; it refuses to overwrite an existing source directory. `build.py` compiles with `-O2 -g0`, static project libraries, no OpenMP, and `make -j1`, using local dependencies in `../exact_algebra_backend_root/usr`.

`validate.py`, `guard_check.py`, and `arithmetic_check.py` save all inputs, outputs, and logs. Solver comparisons use a 20-second child wall limit and a 2-GiB address-space limit; rejection tests use 10 seconds. Run reproductions in a fresh artifact directory because saved solver outputs are never overwritten.
